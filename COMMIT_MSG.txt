Fix BUGS.md #9 (cache keying), #10 (fat-pointer return), #11 (clippy)

BUG #9  vtable_method_map static cache ignored inputs
   Replaced the single static M: OnceLock<…> with a process-wide
   Mutex<HashMap<CacheKey, OnceLock<Arc<HashMap<…>>>>> keyed on
   (image_base, declared-fingerprint). Steady-state lookups are
   lock-free (OnceLock::get() returns the cached Arc); the mutex is
   only held on the very first request per (PE, corpus) pair. A
   multi-tenant build (test binaries, fuzz harnesses, workspace-
   wide verifications) now gets fresh entries per target.

BUG #10 vtable_table! macro truncated fat pointer to u32
   The generated function previously returned `u32` (the low 32
   bits of the data pointer, dropping the array length). Changed to
   `*const [usize; #slots]` — the fat-pointer type preserves both the
   data pointer AND the compile-time-known length. Callers that only
   need the data pointer can coerce with `as *const usize` at the
   call site. Doc comment updated.

BUG #11 test_has_direct_branch_target_called_function never_loop
   The `for callee in cg.call_targets() { …; return; }` always
   returned on the first iteration, which clippy::never_loop flags
   as a structural bug. Replaced with
   `if let Some(&callee) = cg.call_targets().iter().next() { … }` —
   functionally equivalent, clippy-clean.
